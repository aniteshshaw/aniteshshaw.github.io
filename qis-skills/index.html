QIS-Skills

The checklist a senior QA lead runs in their head, written down for Copilot.

QIS-Skills is my library of GitHub Copilot agent skills for quality work. Each one reviews a story, designs tests, writes Playwright code, checks a PR, or files a defect the way an experienced engineer would, and then waits for a person to approve the result. It grew out of QIS, the agent workflow my teams use every sprint, which cut QA analysis and design effort by 60–70%.

Why I built it

Good QA judgment didn't scale past a few people

Copilot can produce tests and review comments all day. My problem was that a lot of what it produced looked right and wasn't. So I started writing down what my best engineers check, step by step, and turned each checklist into a skill.

What I kept seeing

  • The good questions lived in two or three senior heads
  • Vague stories reached the sprint and came back as rework
  • Generated tests used selectors that didn't exist
  • PR review depended on who had time that afternoon
  • Test evidence sat in CI logs that nobody opened
→

What the skills changed

  • A new engineer runs the same checks a veteran would
  • Gaps get raised before planning instead of mid-sprint
  • Locators come from the real code, every time
  • Every test PR gets the same six checks, and a person signs off
  • Results land on the story, where people actually look
The pipeline

One skill per stage, from new story to release

The core skills chain together. Each produces something the next one uses, so quality builds up through the sprint instead of getting checked at the end.

How it's built

What's inside a skill

A skill is a small folder of Markdown. Here's what happens between typing a question in Copilot Chat and getting something you can use.

  1. 01 · The package 
    qis-<skill>/
├─ SKILL.md     # playbook
├─ references/  # on demand
└─ scripts/     # helpers

    Plain files in Git. You can review a skill the same way you review code.

    no black boxes
  2. 02 · The trigger 
    ---
name: qis-<skill>
description: >
  Use when someone asks
  "is this story ready?"
  or wants AC checked…
---

    Copilot reads the description and picks the right skill for a plain-English request.

    the description is the router
  3. 03 · The playbook
    • Required checks before it starts
    • Look things up in the code and tracker
    • Only ask what it can't find
    • Never touch credentials

    The steps a senior engineer would follow, in order, every time.

    discipline, not vibes
  4. 04 · The hand-off
    • Draft → you approve → post
    • Everything traced to a story and AC
    • Evidence attached to the work item

    The agent does the legwork. A person makes the call.

    you stay in charge
House rules

Four rules every skill follows

01

Look it up, don't make it up

Locators, validation rules, and existing coverage come from the actual code and tracker.

02

A person approves

Skills draft and score. Nothing gets posted to a PR or exported to the tracker until someone says yes.

03

Everything traces back

Each test, finding, and bug links to a story and an acceptance criterion. No orphans.

04

Easy to adapt

Plain Markdown with generic examples, so a team can tailor one to its own stack in an afternoon.
