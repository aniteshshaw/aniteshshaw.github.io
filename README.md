# Anitesh Kumar Shaw — Portfolio

Fully static, pre-rendered personal portfolio. Plain **HTML + CSS + a little vanilla JS** — no
framework and no client-side content injection. Every word of content lives in the served HTML, so
search engines, link previews, and recruiter tools all see the real page. JavaScript only adds motion
(scroll reveals, the flywheel, the Copilot-chat demo) and the catalog filters.

## Structure

| Path | What it is |
|------|------------|
| `index.html` | Home: hero, AI enablement playbook, impact, QIS-Skills band, the book, experience, builder, writing, credentials, about, contact. |
| `qis-skills/index.html` | QIS-Skills product page. Hand-written copy plus **generated regions** (`<!-- qis:begin … -->`). |
| `qis-skills/<skill-id>/` | One generated page per public skill. Right now every skill is private, so there are none. |
| `personal/index.html` | Builder page: A2Quest, QIS-Skills, Bhaktiverse, the book. |
| `resume/index.html` | Public résumé page, generated by `private/resume/build-resume.mjs`. |
| `css/style.css` | Design system (navy/amber, blueprint/sketch language), layout, responsive rules. |
| `js/main.js` | Nav, reveals, counters, filters, chat demo. Progressive enhancement only. |
| `tools/publish-skills.mjs` | Publishes the private skill catalog into the static site. |
| `tools/studio.mjs` + `studio.html` | **QIS-Skills Studio**, a local control panel for what's public and when. |
| `studio/catalog.json` | **Private** master catalog. Git-ignored and never committed. |
| `private/` | **Private, git-ignored**: résumé sources, repo backups, the sensitive-terms guard, review notes. |

## Run locally

```bash
python3 -m http.server 8420     # the site → http://localhost:8420
node tools/studio.mjs           # the Studio → http://127.0.0.1:8421
```

## Controlling which QIS-Skills are public (and when)

The full catalog, including skills you're not ready to show, lives in `studio/catalog.json`. That file
is git-ignored, so it never reaches GitHub. Only what you publish gets written into the site.

| Status | What the public site shows |
|--------|----------------------------|
| `live` | Full skill page plus a catalog card. `featured: true` adds a "Flagship" badge. |
| `preview` | Full page with a "Preview" badge. |
| `coming-soon` | A teaser in "Coming next" with name, tagline, and date only. |
| `hidden` | Nothing. |
| `publishAfter: "YYYY-MM-DD"` | On or after that date, the next publish makes the skill `live`. |

Workflow:

1. `node tools/studio.mjs` → toggle status, Flagship, and "Goes live on" → **Save & publish**
   (or edit the JSON and run `node tools/publish-skills.mjs`).
2. Preview with `--dry-run`, or check a future date: `node tools/publish-skills.mjs --date 2026-11-01 --dry-run`.
3. Review at `localhost:8420`, then `git add -A && git commit && git push`.

Scheduled dates take effect at the next publish. To change wording, a skill's flow diagram, or its
demo script, edit that skill in `studio/catalog.json` and publish.

**Back up `studio/catalog.json`.** It isn't in Git. The Studio keeps its last 25 saves in
`studio/backups/`, but those only exist on this machine. A copy in the private QIS-Skills repo is a
good home, and `QIS_CATALOG=/path/to/catalog.json` points the tools at it.

## Deploy to GitHub Pages (root deploy)

Repo **Settings → Pages** → Source = **Deploy from a branch** → branch `main`, folder `/ (root)`.
`.nojekyll` is included so all files are served as-is.

## Keeping client data out of Git

A pre-commit hook (`private/guard/pre-commit`, installed into `.git/hooks/`) blocks any commit
that adds employer or client identifiers, or any file under `private/` or `studio/`. The term list
lives in `private/guard/sensitive-terms.txt`, outside Git. Hooks are local, so after a fresh clone
copy the hook back in: `cp private/guard/pre-commit .git/hooks/`.

## Résumé

Edit `private/resume/resume-data.mjs`, then:

```bash
node private/resume/build-resume.mjs    # .docx files + resume/index.html
sh private/resume/export-pdf.sh         # PDFs via Pages (open Pages first)
```

The public PDF (`assets/resume.pdf`) and page are generic. The application copy, which names
employers, stays in `private/resume/out/`.

## Editing other content

- **Home / Builder / Résumé copy** lives directly in the HTML. Edit the relevant `<section>`.
- **Live skill counts** (`<span data-qis="live-count">`) are kept in sync by the publisher on every page.
- **Credentials**: `.cred-row` in `index.html` and `resume/index.html`. Use issuer name and cert name, no logos.
- **Résumé**: never hand-edit `resume/index.html` or `assets/resume.pdf`; rebuild them (above).
